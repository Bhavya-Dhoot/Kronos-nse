Add a new function `check_mve_health` at the end of `data/quality/checks.py` (before any trailing blank lines).

**Signature:**
```python
def check_mve_health(mve: Any | None) -> dict[str, Any]:
```

**Parameters:**
- `mve: Any | None` — The MarketVarianceEngine instance, or None (if MVE is not configured). Uses `Any` to avoid importing MarketVarianceEngine (keeps checks.py free of cyclic imports). The `data/quality/gate.py` caller is responsible for passing the engine.

**Behavior per D-01 through D-04:**

1. **If `mve is None` or MVE not available** (e.g., unconfigured):
   - Return: `{"passed": True, "critical": False, "detail": "MVE not configured — check skipped.", "active_dimensions": 0, "stale_dimensions": [], "circuit_broken_dimensions": []}`
   - Per D-01: warning-level, non-critical → `"critical": False`

2. **If MVE is available:**
   - Read `health = mve.health_status` (dict with ready, degraded, active_dimensions, collectors)
   - Read `scores = mve._scores` (dict[str, ScoreEntry]) to determine staleness
   
   **Determine active dimensions:** From health_status["active_dimensions"] (integer count). Per D-02:
   - `active_dimensions: str` — format as `"{count}/{total}"` where total is len(mve._collectors) or len(health["collectors"])
   
   **Determine stale dimensions** per D-02:
   - A dimension is stale if it has `first_poll: True` but its `collected_at` is older than DQG's staleness threshold (use same `max_staleness_seconds_live` from DQG config, default 30s).
   - Compare `collected_at` (ISO timestamp string) against current time using `datetime.now(timezone.utc)`.
   - Return list of dimension names that exceed the threshold, or (simpler/better) use the `is_stale` flag from the ScoreEntry dict since the engine already tracks staleness per dimension.
   - Per D-02: `stale_dimensions: list[str]` — dimension names where last poll >30s ago
   
   **Determine circuit-broken dimensions** per D-02:
   - From `health["collectors"]` dict, find collectors where `is_available` is False.
   - Per D-02: `circuit_broken_dimensions: list[str]` — dimension names in circuit-breaker state

3. **Check logic per D-04:**
   - Pass if `active_dimensions >= 3` (matches engine ready gate from Phase 6 D-11)
   - Warn (still `passed=True` but note in detail) if any circuit-broken dimensions exist
   - The check itself still passes because it's warning-level — but the detail field notes the issue
   
   **Return dict structure:**
   ```python
   return {
       "passed": True,  # warning-level — always passes per D-01
       "critical": False,  # non-critical per D-01
       "detail": str,  # Human-readable summary
       "active_dimensions": str,  # e.g. "4/7"
       "stale_dimensions": list[str],  # names or empty list
       "circuit_broken_dimensions": list[str],  # names or empty list
   }
   ```

4. **Detail formatting examples:**
   - Healthy: `"MVE health: 7/7 active, 0 stale, 0 circuit-broken"`
   - Degraded: `"MVE health: 3/7 active, 2 stale (vix, options), 1 circuit-broken (oi)"`

**Important:** This function does NOT accept a DataFrame — it accepts an MVE engine object. This is different from all other DQG checks and is intentional per D-03: "add check function to checks.py" — the check signature is unique because it reads from the engine rather than OHLCV data.

Add the import to the top of `checks.py` if needed — you'll need `datetime` and `timezone` which are already imported.
