  <action>
Modify the `predict()` method in KronosEngine to call the modifier at two points:

**Point A — Pre-inference (before model predict, around line 231):**

Replace:
```python
pred_df, meta = self._predictor.predict(
    df, x_ts, y_ts, ... temperature=temperature, ...
)
```

With:
```python
# Pre-inference: MVS temperature adjustment
effective_temp = temperature
if self._modifier is not None:
    effective_temp = self._modifier.modify_pre_inference(
        temperature if temperature is not None else self.temperature
    )

pred_df, meta = self._predictor.predict(
    df, x_ts, y_ts, ..., temperature=effective_temp, ...
)
```

Per D-09: modify_pre_inference() is called before `self._predictor.predict(...)`.

The logic:
- If `temperature` is None (caller wants default) → pass `self.temperature` to modifier
- If `temperature` is set (e.g., from regime override) → pass that value
- Modifier returns the effective temp per D-05

**Point B — Post-inference (after result dict built, around line 254):**

After `result = self._df_to_result(...)` and before `await self.redis.set_prediction(...)`, add:

```python
# Post-inference: MVS modifications (bias, bands, constraints, confidence)
if self._modifier is not None:
    result = self._modifier.modify_post_inference(result)
```

Per D-18 through D-19: post-inference applies bias → bands → constraints → confidence on the result dict.

**Important:** The `result` dict now may contain `"mve_confidence"` key set by the modifier. This flows through Redis cache and persist — the key is harmless for consumers that don't check it, and is checked by:
- `api/helpers.py` — `compute_confidence()` checks `mve_confidence` (Plan 03)
- `HeadlessRunner._compute_signal()` — reads MVS directly from engine.mve (Plan 03)

**Update `_df_to_result()` meta handling** — the `meta` dict from predictor doesn't include mve_modifications. Keep existing meta extraction. If the modifier adjusted temperature, the `effective_temp` should be reflected in the result. Update line in _df_to_result:
- `"temperature": meta.get("temperature", self.temperature)` — this already captures the temp passed to predict(). Since we pass effective_temp to self._predictor.predict(), meta["temperature"] will be effective_temp. This is correct — the result reflects the MVS-adjusted temperature.

**No changes needed to `predict_symbol()`** — it already computes effective_temp from context_builder and passes it to predict(). The modifier is called inside predict().
