**Update `compute_confidence()` function** (lines 26-35):

Per D-20: "API helpers (compute_confidence in api/helpers.py) also check mve_confidence flag on the prediction dict and override if present"

Change the function signature and logic:

```python
def compute_confidence(
    pred_close: list[float],
    last_close: float | None,
    *,
    mve_confidence: str | None = None,  # NEW: override from MVS
) -> str:
    """Classify confidence from expected move magnitude, with MVS override."""
    # MVS override takes precedence per D-20
    if mve_confidence is not None:
        return mve_confidence
    
    # Existing logic unchanged
    if not pred_close or not last_close:
        return "LOW"
    move_pct = abs(float(pred_close[-1]) - last_close) / last_close * 100
    if move_pct >= 1.0:
        return "HIGH"
    if move_pct >= 0.3:
        return "MEDIUM"
    return "LOW"
```

Key behavior per D-20/D-21:
- If `mve_confidence` is provided (not None), return it immediately — this is the MVS override.
- If not provided, fall through to existing move-based confidence calculation.
- Direction is unaffected per D-21.

**Update `engine_result_to_prediction()` function** (lines 95-126):

return PredictionResponse(

This ensures API responses reflect the MVS confidence override when the modifier set `mve_confidence` on the prediction dict.
